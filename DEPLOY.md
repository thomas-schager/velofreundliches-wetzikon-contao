# Deployment Guide — VeloWetzikon Contao

This document describes every step needed to move the local Contao installation
to the production web host. Keep it up to date whenever the local setup changes.

---

## Prerequisites

### Local machine
- PHP >= 8.1 (currently 8.5)
- Composer >= 2
- Git

### Web host requirements
- PHP >= 8.1 with extensions: `intl`, `dom`, `mbstring`, `gd` (or `imagick`), `pdo_mysql`, `zip`, `openssl`, `curl`
- MySQL / MariaDB >= 5.5
- SSH access (strongly recommended)
- A dedicated web root that can be pointed to the `public/` sub-folder
- `composer` available on the host, OR the ability to upload a pre-built `vendor/` folder

---

## 1. Local Development Setup

### First-time installation
```bash
# Already done — Contao 5.7 installed via:
composer create-project contao/managed-edition . 
```

### Environment file
Copy `.env` to `.env.local` and fill in your local database credentials:
```
DATABASE_URL=mysql://user:password@127.0.0.1:3306/velowetzikon
APP_SECRET=<random 32+ char string>
```

`.env.local` is git-ignored and never committed.

### Run locally
```bash
# PHP built-in server (quick test only, not for production)
php -S localhost:8000 -t public/
```

Or configure a virtual host in your local web server pointing to `public/`.

### Contao Install Tool
Visit `http://localhost:8000/contao/install` to:
1. Set the database credentials (if not done via `.env.local`)
2. Run the database migrations
3. Create the first admin user

## 2. Git Workflow

### What is committed
| Path | Committed | Reason |
|---|---|---|
| `composer.json` | Yes | Dependency definitions |
| `composer.lock` | Yes | Reproducible installs |
| `system/config/` | Yes | App config (not `localconfig.php`) |
| `templates/` | Yes | Custom templates / theme |
| `.env` | Yes | Default env vars (no secrets) |
| `vendor/` | No | Re-installed via Composer |
| `public/` | No | Generated by Contao |
| `assets/` | No | Generated component assets |
| `files/` | No | User uploads (managed separately) |
| `var/` | No | Cache & logs |
| `.env.local` | No | Contains secrets |

### Push to GitHub
```bash
git remote add origin git@github.com:YOUR_USER/YOUR_REPO.git
git push -u origin main
```

## 3. Deploying to the Web Host

### 3.1 First deployment

**On your local machine:**
```bash
git push origin main
```

**On the web host (via SSH):**
```bash
# Clone the repository into a staging folder
git clone git@github.com:YOUR_USER/YOUR_REPO.git /path/to/site

cd /path/to/site

# Install PHP dependencies (production mode, no dev packages)
composer install --no-dev --optimize-autoloader

# Copy and edit environment file
cp .env .env.local
nano .env.local          # Set DATABASE_URL and APP_SECRET
```

**Point the web host's document root to** `public/` (not the project root).

**Run the Contao setup:**
```bash
php vendor/bin/contao-setup
```

Then visit `https://yourdomain.com/contao/install` to finalize the database
migration and create the admin account.

### 3.2 Subsequent deployments

```bash
# On the web host
cd /path/to/site

git pull origin main

# Install/update dependencies if composer.lock changed
composer install --no-dev --optimize-autoloader

# Run any pending Contao migrations
php vendor/bin/contao-migrate --no-interaction

# Clear the cache
php bin/console cache:clear --env=prod
php bin/console contao:symlinks
```

## 4. File Uploads / User Content

The `files/` folder contains user-uploaded media and is **not** in Git.

Options for keeping it in sync:
- **rsync** (recommended):  
  ```bash
  rsync -avz files/ user@host:/path/to/site/files/
  ```
- FTP/SFTP upload via a file manager.
- Shared cloud storage (e.g. S3 with a Contao filesystem adapter).

---

## 5. Database

The database is also **not** in Git.

### Export (local → host)
```bash
# Dump local database
mysqldump -u root velowetzikon > velowetzikon_$(date +%Y%m%d).sql

# Upload and import on the host
scp velowetzikon_*.sql user@host:/tmp/
ssh user@host "mysql -u dbuser -p dbname < /tmp/velowetzikon_*.sql"
```

### Migrations only (after code updates)
```bash
# On the host, after git pull + composer install
php vendor/bin/contao-migrate --no-interaction
```

## 6. Environment Variables Reference

| Variable | Description |
|---|---|
| `DATABASE_URL` | `mysql://user:password@host:3306/dbname` |
| `APP_SECRET` | Random secret string (generate with `openssl rand -hex 32`) |
| `MAILER_DSN` | SMTP config, e.g. `smtp://user:pass@smtp.host:587` |

---

## 7. Checklist Before Going Live

- [ ] `APP_ENV=prod` set in `.env.local` on the host
- [ ] `APP_DEBUG=0` set in `.env.local` on the host
- [ ] Strong `APP_SECRET` set (different from local)
- [ ] SSL certificate active (`https://`)
- [ ] Web root points to `public/` subfolder only
- [ ] `php bin/console cache:clear --env=prod` run
- [ ] Contao Install Tool password set or Install Tool locked
- [ ] Cron job configured for Contao periodic commands:
  ```
  * * * * * php /path/to/site/bin/console contao:cron
  ```
- [ ] `files/` directory uploaded
- [ ] Database imported and migrations run
- [ ] Test login to Contao backend (`/contao`)
